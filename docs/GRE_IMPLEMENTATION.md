# GRE forwarding model

The tunnel OSPF neighbor stays Full throughout. This is a direct two-router topology with static inner LAN routes, so it does not prove multihop convergence or every failure mode. The full production browser suite passes 22/22 and the latest repository check passes 348 tests, TypeScript and optimized build. Broader GRE and OSPF release limits remain open.

Update 2026-10-12: IOS routers can configure a point-to-point IPv4 GRE interface with `interface Tunnel0`, an interface address, `tunnel source <physical-interface>`, `tunnel destination <IPv4>`, `tunnel mode gre ip`, and `no shutdown`. A static route can name the tunnel as its outgoing interface. The packet engine wraps the routed IPv4 PDU in an outer IPv4 packet, sends that packet through the ordinary underlay route and ARP path, checks the remote source/destination pair against an operational tunnel, then decapsulates and routes the inner packet. The decapsulator decrements the inner IPv4 TTL as specified by [RFC 2784](https://www.rfc-editor.org/rfc/rfc2784.html).

IOS `keepalive [seconds [retries]]` is modeled for GRE tunnels. Defaults are 10 seconds and 3 retries; `keepalive 0` disables it, and `no keepalive` restores the default. The simulator sends a semantic GRE request through underlay routing/ARP, matches a reply to the configured peer, marks the tunnel down after missed replies, withdraws its route from the active routing table, and restores the route after a valid reply. The peer can answer while its own keepalive state is down, provided its physical underlay source remains available. The command and interval survive workspace and PKT XML configuration round trips. OSPFv2 and RIPv2 control packets can cross GRE, exchange routes and carry a real returned LAN echo flow. The production browser acceptance completes a Simple PDU across the OSPF/GRE primary path and after failover to a floating-static backup; the RIP browser flow checks tunnel route withdrawal and recovery. The IOS ranges follow [Cisco's GRE keepalive documentation](https://www.cisco.com/c/en/us/support/docs/ip/generic-routing-encapsulation-gre/63760-gre-keepalives-63760.html).

`show ip route`, `show ip interface brief`, and `show running-config` report the configured interface and route. Extended ACLs can match GRE protocol 47. Physical chassis views and exported PKT module-port lists omit virtual tunnel interfaces. GRE configuration and tunnel static routes survive workspace restore and the app's XML export/import path.

Regression evidence is in `src/simulator/gre.test.ts`: a PC-to-PC ping crosses two configured routers and returns an echo reply; changing one endpoint causes a visible drop; `no shutdown` reports down/down when the source interface is down; and GRE forwards over both OSPF-selected underlay paths after primary shutdown and recovery. A separate RIPv2 test learns the remote LAN through Tunnel0, shuts the preferred egress and verifies the returned PC ping exits the backup interface; its reply route is static. `src/simulator/ospf.test.ts` and `src/simulator/rip.test.ts` prove the learned OSPF and RIP LAN routes are withdrawn after GRE keepalive failure and restored after the peer returns; OSPF also re-establishes a Full adjacency. RIP recovery currently waits for the peer's next periodic update, with the regression allowing up to 750 simulation ticks. Both test files configure two-router tunnel labs, exchange OSPFv2/RIPv2 control PDUs, learn the remote LAN and return a PC-to-PC echo. `e2e/gre.spec.ts` uses the production browser build to configure Tunnel0, observe keepalive-driven failure/recovery, and check down/down state and learned routes. Browser coverage now also verifies dynamic OSPF's GRE endpoint route moves primary-to-backup-to-primary, with successful PC Simple PDUs on each path and a Full tunnel neighbor; a separate test covers the floating-static backup fixture with cold ARP. `src/simulator/workspaceSchema.test.ts` checks persisted endpoint state and rejects an invalid destination. `src/simulator/acl.test.ts` checks GRE ACL matching and rejects meaningless transport-port clauses. PKT configuration round-trip is covered in the GRE test plus the existing encoder/import tests.

The RIP backup-egress regression removes Router A's static destination route, learns the LAN through RIPv2 on Tunnel0, then verifies the route remains after the preferred underlay egress shuts and a returned ping's GRE packet uses the backup. The reply side still uses a static route, so symmetric dynamic failover remains open.

Production browser acceptance in `e2e/gre.spec.ts` observes the RIP route over Tunnel0, removes it after a mismatched peer destination causes keepalive failure, repairs the peer, and confirms the route returns. The OSPF browser flow also proves GRE payload delivery over both primary and floating-static backup underlays. The full production-browser suite passes 15/15.

This is a structured teaching model, not raw GRE bytes. It supports IPv4 payloads and physical-interface source names. Browser dynamic OSPF failover is verified only for a direct two-router dual-link underlay with static inner LAN routes. Keepalive timing uses accelerated simulation ticks and semantic request/reply fields rather than Cisco's exact wire packet encoding or wall-clock scheduling. Failure and recovery are tested with a mismatched remote tunnel destination while the physical underlay stays up; whole-router power loss and every failure mode are not covered. Full OSPF/RIP convergence through all tunnel failure modes, multihop and multipath topologies, IPv6 GRE, GRE over IPsec, redundancy/state synchronization, full IOS command parity, and instructor acceptance remain outside this slice. An internal encoder/import round trip is not proof that the exported file behaves identically in the college's official Packet Tracer version. GRE implementation remains partial and does not close the release gate.
