# Spanning Tree implementation

wireX now models switch-to-switch spanning-tree control traffic as animated, link-local packet frames. For each configured or carried VLAN, an active switch advertises its bridge ID, selected root bridge ID, and root path cost. A receiving switch accepts the advertisement only when the frame arrives from the connected peer on a port that carries that VLAN. The receiver records the neighbor and recalculates its own root on a later simulation tick, so a priority change reaches peers through packet exchange.

The simulation sends an initial advertisement when the STP state or advertised vector changes, then refreshes it every 34 ticks. At the current 60 ms canvas tick, that is approximately 2.04 seconds. Each valid received BPDU refreshes the neighbor's age. A neighbor expires after 334 ticks, approximately 20.04 seconds, without a valid advertisement. Realtime simulation continues advancing these control frames while the topology has active switch links and no student traffic is in flight. In Simulation mode, Capture / Forward advances them only while the simulation is playing or the user steps it. The queue remains capped at 256 frames. Parallel EtherChannel links use one active member for a BPDU to avoid duplicate control traffic.

Changed configuration advertisements are rate-limited independently for each port and VLAN. After any BPDU, a changed vector waits at least 17 ticks (1.02 seconds) before another is sent; unchanged vectors use the longer 34-tick hello interval. This bounds rapid control-plane changes without suppressing periodic liveness advertisements.

The STP runtime is transient. Workspace and training checkpoints remove it, and loading a topology resets it so fresh advertisements establish the root again. A dead link or a bridge ID that no longer matches the advertised root removes that neighbor from the local election.

Newly connected switch ports are physically up immediately so BPDUs can establish a tree, while their user-data state starts in LISTENING. After 250 simulation ticks (15 seconds) it enters LEARNING, and after another 250 ticks it enters FORWARDING. PortFast and the switch `spanning-tree portfast default` setting bypass both delays. LISTENING drops data before source learning; LEARNING records the source but still drops user data; only FORWARDING can transmit user traffic. The physical carrier state stays separate from the STP forwarding state.

Switch ports store an independent state and start tick for each VLAN they carry. A trunk can block one VLAN while forwarding another, with a separate 15-second timer for each VLAN. When an active trunk begins carrying a VLAN that has no runtime entry yet, that VLAN starts in LISTENING. The packet engine and `show spanning-tree vlan N` read the state matching the packet or requested VLAN. The port LED shows amber if any carried VLAN is not forwarding.

Tests cover per-VLAN advertisements, hello refresh timing, root election after received BPDUs, max-age expiration and refresh boundaries, stale-neighbor removal after link failure, changed-vector hold timing, timed per-VLAN port startup, independent trunk forwarding and timers, new VLAN startup, PortFast bypass, packet forwarding differences between VLANs, dynamic MAC refresh and exact expiry, runtime cleanup on save/load, idle realtime timers, bounded EtherChannel traffic, and packet recovery after topology changes. Production-browser acceptance loads two switches into an otherwise idle canvas, confirms Switch-A learns Switch-B as the VLAN root, and verifies `show spanning-tree vlan 1` reports the learned root. Store integration runs the default enterprise lab for 510 ticks and verifies all four switches learn a VLAN 1 root, five valid two-member EtherChannels form, both redundant logical paths block and a PC-to-server ping drains within the link-count queue bound. After matching VLAN 10/20 access and trunk configuration was added, a second store regression confirms Switch1/Switch2 win their intended VLAN roots and sends successful pings in both directions across the opposite access switches for both VLANs. The production-browser test checks the default campus configuration and per-VLAN root learning. Duplicate physical port use, inconsistent legacy bundle labels and manually forced physical `learning` state were corrected. The production browser suite passes 26/26; the complete check passes 381 tests.

Dynamic switch MAC entries expire after 300 simulated seconds, or 5,000 ticks at 60 ms per tick. Traffic refreshes the source entry. Realtime continues to advance the clock while learned entries remain, including when no packets are in flight. Persistence stores the displayed age in seconds but removes the run-specific last-seen tick; loading starts the remaining timer from the preserved age. Engine tests cover expiration and refresh boundaries, while store and persistence tests verify idle ticking and cleanup.

This remains a partial STP model. Imported or reloaded labs clear transient STP state and relearn through fresh advertisements. Switch root selection and port roles now use received BPDU vectors, but do not model all Cisco STP state-machine details. Topology-change notifications, independently verified role convergence after real root/link failures, EtherChannel member failure and recovery, large-topology behavior and instructor acceptance remain release blockers in `REPLACEMENT_GATES.md`. The new VLAN 10/20 campus tests verify same-subnet traffic across the trunk tree, not inter-VLAN routing or gateway redundancy.
