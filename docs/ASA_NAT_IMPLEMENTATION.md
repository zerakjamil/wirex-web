# ASA dynamic PAT implementation

Updated 2026-10-12. The ASA 5505 teaching model supports bounded stateful ICMP Echo, basic UDP, TFTP read PAT with transfer-port inspection, and simulated TCP/HTTP PAT.

When an echo request enters an ASA interface whose `nameif` matches a configured `dynamic-pat` rule, the destination route exits through the rule's destination interface, and the source belongs to the rule's IPv4 CIDR, the simulator changes the source address to the outside interface address. It allocates an ICMP identifier and records the inside address, remote destination, both identifiers, interfaces, and a 60-second expiry. The outside host returns a normal echo reply. The ASA accepts it only when its outside address, remote source, translated identifier, and live entry match, then restores the inside destination and original identifier before routing the packet.

`show xlate` lists live sessions. `show running-config` renders configured dynamic PAT as an ASA network object and interface overload command. ASDM displays the actual configured rules and live translation entries. Reset Simulation clears runtime translations, and workspace restore discards them while preserving rule configuration. Malformed or duplicate rules, invalid CIDRs, and unknown interface names are rejected during workspace admission.

For UDP requests, PAT replaces the source port with a unique high port and records the original client port, destination address/port, translated outside address/port, and interfaces. Basic request/reply services accept only the recorded remote address and port. For a TFTP read, the helper accepts the first DATA block only from the requested server IP and the translated outside port, learns its server-selected source port, and pins that port to the live translation. Later DATA and ACK packets must use that learned endpoint. The ASA restores the inside destination address and client port before routing each response. ASDM's UDP inspection and separate TFTP inspection controls gate the return path and helper. Both default to enabled for existing imported configurations.

For the simulator's structured TCP/HTTP flow, PAT replaces the client's source address and TCP port on every outbound segment and records the remote address and service port. The HTTP server replies to the translated client IP and port. The ASA restores the original client address, port, and TCP client metadata for matching return segments, including the handshake, data, acknowledgments, and close. The existing TCP inspection control governs matching return segments. This is the application's HTTP transport model, not a general-purpose TCP stack or raw TCP packet implementation.

Regression coverage exercises inside ICMP and UDP requests through the ASA to an outside Server-PT responder, a 700-byte TFTP file through learned transfer-port PAT, and a full HTTP GET through translated TCP handshake, request/response data, acknowledgments, and close. Tests check unmatched identifiers/ports, disabled ICMP/UDP/TCP/TFTP inspection, invalid ICMP identifier and transport ports, unsupported static NAT, `show xlate`, running-config output, persistence, and simulation reset. Production browser checks verify the ASDM rule and inspection controls.

This implementation does not provide TCP applications beyond the simulator's HTTP model, static NAT, port forwarding, NAT exemption or order, NAT rule editing commands, TFTP uploads, option negotiation, transfer retries, full ASA connection tracking, or raw packet bytes. Static NAT is rejected with an explicit simulator error. Dynamic PAT translates ICMP Echo, basic UDP tuples, TFTP reads with a learned transfer port, and the structured TCP/HTTP flow. The 60-second timeout uses wall-clock time, and translation state is an educational packet model rather than an ASA dataplane implementation. GRE and redundancy are separate open release gates.
