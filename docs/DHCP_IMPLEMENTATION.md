# DHCP packet exchange

## Enterprise campus relay, 2026-10-13

The default enterprise lab configures the Work Office Server with VLAN 10 and VLAN 20 pools. Switch2's VLAN 20 SVI relays to 192.168.10.11. Routed Offer/ACK messages now pass through intermediate L3 switches and are rebroadcast through active ports carrying only the originating VLAN. Store integration and production-browser acceptance complete DORA for PC2 and verify 192.168.20.4/24, gateway 192.168.20.1, DNS 192.168.10.11 and the correct DHCP server. The lease starts at `.4` because `.1` is the HSRP virtual gateway and `.2`/`.3` are the two physical VLAN 20 SVI addresses. A wrong helper address produces a failure naming the configured IP and `Switch2 Vlan20`, while leaving the client unconfigured. `rtk npm run check` passes 386 tests and the production browser suite passes 27/27. This adds campus relay coverage; the instructional timer and option limitations below remain.

## Browser acceptance update, 2026-10-12

Production browser tests cover direct lease assignment, T1 renewal, T2 rebinding and expiry, fresh discovery, MAC-matched manual reservation, single-address conflict/replacement and a wrong-pool diagnosis. The reservation flow verifies the assigned host address plus mask, gateway, DNS, server and Bound state in Desktop IP Configuration. The T2 flow verifies the old lease settings clear before rediscovery; the conflict flow verifies a named claimant warning, does not apply the disputed address and binds the replacement. Multiple reservation collisions remain untested in the browser.

DHCP clients now send an animated Discover on their connected interface. A server on the same VLAN can return an Offer directly. Routers with `ip helper-address` relay Discover and Request messages to a remote server, then forward Offer and ACK messages back onto the original client VLAN. The client applies the address, mask, gateway and DNS server only when the ACK reaches its interface.

Pool selection continues to use the configured pool subnet, excluded ranges and addresses already present on devices. Active leases are reserved across clients, and configured default-router, DNS and TFTP addresses are also reserved. A server declines a request if the offered address is no longer available. An inbound ACL that blocks UDP port 67 produces a DHCP failure with the interface and ACL name. When an exchange drains without an ACK, the client receives a pool and VLAN diagnosis.

Before applying an ACK, the client broadcasts an ARP probe for the offered address while its source address is still `0.0.0.0`. A reply rejects the lease with the claimant's device name when available, leaves the client unconfigured, and triggers a bounded replacement Discover. The next offer is selected against currently configured host addresses, so a conflicting static address is skipped.

IOS manual bindings are supported as one `host <ip> <mask>` pool per client, matched by either `client-identifier` or `hardware-address`. Host pools reserve their addresses from dynamic allocation, appear in `show ip dhcp pool` and `show running-config`, and survive workspace and imported running-config restoration. If no host binding matches and no dynamic network pool exists on that subnet, the failure identifies the expected client identifiers and recommends a dynamic pool. A host pool cannot mix `host` and `network` statements or use both identifier methods, following the [Cisco IOS XE DHCP manual-binding guide](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/ipaddr_dhcp/configuration/xe-16-12/dhcp-xe-16-12-book/config-dhcp-server-xe.html).

Pools accept Cisco IOS `lease <days> [hours] [minutes]`; omitted lease configuration defaults to 86,400 seconds. A client records the ACK time and granted duration, renews at 50 percent of the lease, rebinds at 87.5 percent, and retries a missed renewal every two seconds. At expiry the old address, gateway and DNS settings are cleared before a fresh Discover is sent. The Desktop IP Configuration panel reports the server, lease state and remaining time. `show ip dhcp binding` lists active leases and time remaining; `show ip dhcp pool` and `show running-config` expose configured durations.

This remains an instructional lease model rather than full DHCP parity. Timers use the app's wall clock and are evaluated while the simulation runs or advances. Authenticated cloud lease storage, the full option set, BOOTP parity and multiple reservation-collision behavior remain open.

Each successful ACK creates a server-side binding with client identifier, hardware address, start time, lease duration and automatic/manual type. Bindings persist with the workspace, reserve addresses if the client disappears, expire with the lease, and appear in `show ip dhcp binding`. `clear ip dhcp binding <address>` and `clear ip dhcp binding *` remove server records. Old saved workspaces without this table retain a read-only compatibility display from client lease data.

Regression coverage includes direct and relayed DORA, delayed client configuration until ACK, offered-address conflict detection and replacement lease acquisition, MAC and client-identifier host reservations, reserved dynamic addresses, unmatched-binding diagnosis, durable server bindings, clear and expiry behavior, configured lease duration, T1 renewal, T2 rebinding, expiry and rediscovery, relay ACL denial, missing helper configuration, subnet exclusions, reserved service addresses, wrong-VLAN diagnosis, IOS pool syntax and workspace persistence.
