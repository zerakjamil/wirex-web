# Routed UDP Echo, NTP, TFTP, SNMP, and Syslog, updated 2026-10-20

Complex PDU can send a UDP Echo request from one addressed device to an IPv4 destination. The request uses an ephemeral source port, a chosen destination port, and a UTF-8 payload. It follows the simulator's ARP, Ethernet, VLAN, route, and ACL pipeline. A Server-PT responds only when UDP Echo is enabled and the destination port is in its configured listener list; the reply reverses the ports and returns the same payload through the route to the client.

Server Config exposes an Enable UDP Echo switch and listener port list. Port 7 is the default listener when no custom list exists. Additional listeners accept ports from 1 through 65535. Workspace import validation rejects malformed service flags and invalid listener ports. The PDU list tracks pending, successful, and failed requests and supports replay with the original port and payload.

Failures are attached to the request when an ACL, link, route, ARP resolution, disabled service, or closed UDP port prevents a response. The client does not display success until the response reaches its source device. IPv4 UDP Echo payloads are limited to 65,507 UTF-8 bytes.

IOS routers support `ntp master [stratum]` and `ntp server <IPv4-address>`. The master answers routed UDP/123 requests with timestamp and stratum data. A client sends a synchronization request when the server is configured, then records its calculated clock offset and resulting stratum only after the response arrives. `show clock`, `show ntp status`, and `show ntp associations` expose the current state. NTP master/client configuration survives workspace restore and imported PKT running configuration. Master stratum defaults to 8 and accepts 1 through 15, matching the [Cisco IOS command reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/bsm/command/bsm-cr-book/m_bsm-cr-n1.html). A client cannot synchronize from a stratum-15 master because its resulting stratum would be 16.

Syslog is a one-way service. Routers and switches accept IOS `logging <IPv4-address>` and `logging trap <0-7>`; the default threshold is 6, so informational and more severe messages are sent. A link-state change emits `%LINK-3-UPDOWN: Interface <name>, changed state to <up|down>` as a structured UDP/514 datagram through the normal ARP, route and ACL pipeline. Server-PT exposes a Syslog service pane that lists the last 200 messages with arrival time, source name/IP, severity and text, and can clear them. Delivery is best effort: an unreachable server, disabled service, path failure or an outbound UDP/514 ACL drops the message without blocking the device action that generated it.

Syslog is a bounded teaching model: there is no local logging buffer, source-interface selection, rate limiting, TLS, RFC 5424 wire encoding, or remote syslog over IPv6. Only link-state events are generated today; configuration, authentication and routing-protocol events remain open.

Server-PT Config can enable a TFTP read service and store UTF-8 text files up to 65,536 bytes. The PC and laptop Desktop includes a TFTP client. A read request uses UDP/69, then the server sends 512-byte DATA blocks from a transfer port and waits for each matching ACK before sending the next block. Exact multiples of 512 bytes receive the required final empty DATA block. The client reports and saves a download only after the final ACK; received files persist with the workspace. The simulator rejects invalid filenames, disabled service, missing files, oversized content and malformed blocks with named errors.

TFTP is a bounded teaching model. It supports RRQ only, uses UTF-8 text content, and does not implement WRQ, netascii conversion, option negotiation, retransmission timers, duplicate/out-of-order recovery, authentication or raw TFTP/UDP byte serialization.

Routers and switches can configure read-only SNMPv2c communities with IOS `snmp-server community <name> ro`; Server-PT exposes an SNMP service panel. The PC/laptop Desktop SNMP Manager sends GET or GETNEXT queries to UDP/161. The model returns four system scalars: sysDescr.0, sysContact.0, sysName.0 and sysLocation.0. Numeric OIDs are ordered for GETNEXT. Unknown GET objects return `noSuchObject`, and a walk past the final scalar returns `endOfMibView`. Wrong communities and unconfigured agents produce visible transaction failures. See `SNMP_IMPLEMENTATION.md` for the exact MIB and IOS scope.

SNMP packet fields are structured simulator metadata, not BER-encoded wire payloads. SNMPv1/v3, SET, traps/informs, views, wider MIB tables and transport retransmission remain open. TFTP upload, option negotiation and recovery also remain open.

Five UDP service tests cover routed NTP request/response, inactive masters, shared-store synchronization, CLI-triggered synchronization and stratum-15 rejection. Six syslog tests cover UDP/514 packet fields, a disabled server, an outbound ACL, IOS `logging` validation, link-state delivery through the store, and `logging trap` filtering; `e2e/syslog.spec.ts` enables the service, configures logging from the CLI, shuts an interface, verifies the received message, and reloads the workspace. The Echo packet/store suite covers routed request/response, returned payload, closed and disabled service, inbound and outbound ACL behavior, invalid target/port/size, shared-store completion, Complex PDU row updates and an unreachable host. TFTP tests cover routed multi-block transfer, the exact-512-byte final block, invalid/disabled/missing-file failures, completed client downloads and workspace persistence. SNMP packet, CLI and schema tests cover GET/GETNEXT, OID errors, authorization failures, client results and configured identity persistence. Additional CLI, workspace and PKT import regressions cover NTP commands, status output and configuration validation.

NTP is an instructional single-query model. Periodic polling, clock discipline over time, authentication, broadcast modes, IPv6 and binary NTP wire serialization remain open. Generic UDP retransmission, ICMP unreachable behavior and raw wire serialization remain open. See `REPLACEMENT_GATES.md` for the complete release requirements.
