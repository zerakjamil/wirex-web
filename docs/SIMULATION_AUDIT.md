## Corrected behavior

- Router subinterfaces use a shared physical parent and MAC, route tagged VLAN traffic, scope ARP/DHCP to the receiving VLAN, support native untagged traffic, and obey parent/child shutdown and subinterface ACLs. Tests reject unknown tags, excluded trunk VLANs and native mismatches, and require an actual returning echo reply.
- RIP/OSPF network configuration is validated in its correct process context. Invalid process IDs and malformed statements leave configuration unchanged. Routing controls with no implementation cannot silently succeed.
- Echo replies use the destination's real routing decision. A missing return gateway cannot produce a successful remote ping.
- Hosts do not learn a remote host's IP address against a gateway MAC. Routers only answer ARP for an address on the receiving interface or matching VLAN SVI.
- Phone PC ports bridge traffic. Access points forward between clients sharing a radio and learn the specific client link for unicast delivery.
- Multilayer switch SVIs route between operational VLANs when `ip routing` is enabled. Gateway exchanges also populate the switch MAC table.
- Native VLAN traffic leaves trunks untagged. Untagged ingress uses the receiving trunk's native VLAN, so a native VLAN mismatch affects actual delivery.
- PKT imports apply VLAN names, SVI metadata, trunk native/allowed VLANs and the routing flag to forwarding state.
- PDU rows become successful only after an actual echo reply returns. They expose actual packet details and failure reasons. Replacing/resetting a topology fails outstanding tests; local interface pings use no invented cable packet.
- CLI route and neighbor output no longer invents OSPF/RIP routes, FULL neighbors or update timers. Configured protocols are identified as preserved configuration whose exchanges are not modeled.
- STP forwarding is checked on frame arrival rather than every animation tick. EtherChannel grouping is calculated when bridge forwarding needs it.

## Capability boundaries

The implemented packet exchange is Ethernet, ARP and ICMP with connected/static IPv4 routing. STP is a steady-state forwarding model. DHCP assignment and supported relay are synchronous; animated DORA, lease expiry and retransmission timers are absent.

Routed TCP/HTTP, DNS A lookup, UDP Echo, NTP, TFTP reads, SNMPv2c reads, OSPF/RIP route exchanges, DHCP DORA/lease behavior, and base IPv4 GRE forwarding have scoped instructional implementations. ASA dynamic PAT handles ICMP Echo, basic UDP, TFTP reads with a learned transfer port and modeled TCP/HTTP with matching reverse paths. Other TCP applications, static NAT, TFTP upload/options/retries, GRE convergence/failover and routing-protocol parity over GRE, redundancy/state synchronization, complete ASA connection state, wireless RF behavior and ARP aging/retries remain unimplemented. Complex PDU submission currently uses ICMP. Preserving a command in configuration does not establish its forwarding behavior.
